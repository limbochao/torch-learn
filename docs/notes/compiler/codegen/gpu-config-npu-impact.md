# GPU 配置在 Ascend NPU 中的影响

原清单共 **48 项**，五个空缺列已逐项补齐。**21 项参与 NPU 的共用 FakeTensor 编译或 NPUGraph/Inductor 路径；另外 27 项在当前 NPU 快照中不支持，性能统一填“否／无影响”**。不支持项包括 6 项 CUDA、20 项 ROCm 和 1 项尚未接入 NPU 的 objgraph 配置。

[完整 11 列 CSV](gpu-config-npu-impact.csv)保留原来的名称、用途、默认值、归属模块、文件和特性，可直接导入表格。[Excel 工作簿](../../../../artifacts/gpu-config-npu-impact-20261124/gpu-config-npu-impact.xlsx)包含原格式的补全表，以及逐项默认判定、生效路径和固定提交源码依据。

这里的 torch_npu 是上述仓库快照。不同发布版、TorchAir 或 npugraph_ex 的独立编译配置需要按各自源码核对。

- **默认是否开启**：假设开源构建、相关环境变量未设置、mode='default' 且没有 options/patch 覆盖。布尔值按 True/False 填是/否。非布尔选项按自身附加控制是否默认配置：None、空列表以及明确表示禁用的 0 填否；有效的数值、非空白名单或编译参数填是。默认启用某个子参数不意味着相应 GPU/NPU 父后端默认运行。例如 capture_sizes=None 的否表示未启用尺寸白名单，允许全部尺寸的行为仍存在。
- **是否影响功能**：判断在 NPU 适用入口修改该项，是否改变编译准入、mutation 处理、捕获边界、异步/异常、诊断或内存管理行为。NPU 不支持或未接入的配置填否，并在功能具体影响点写明“不支持”及对应模块。透明的 FakeTensor 缓存优化填否；功能列的是否不等同于是否改变数学结果。
- **是否影响性能**：以 NPU 实际支持及调用路径为依据，覆盖 host 编译、捕获/重录、调度/同步、device 复制与内存，以及首轮/稳态端到端。**NPU 不支持或未接入的配置统一填否，性能具体影响点写“无影响”**。已支持项写明实际影响的阶段与场景；“是”不代表正向加速，也不代表每次运行必然可测到差异。

### NPU 不支持项的填写规则

NPU 注册了自己的设备 codegen，见 [NPU:__init__.py:257](https://gitcode.com/luqichao/pytorch_new/blob/694f3b371432032d5477fc0d5e47d83aafa7cc09/torch_npu/_inductor/__init__.py#L257)。当前清单的 6 项 CUDA NVCC/NVGEMM 配置和 20 项 ROCm HIP/CK/Origami 配置均没有 NPU 消费路径，功能列填“否”，功能具体影响点以“NPU 不支持该配置”开头，性能列填“否”，性能具体影响点写“无影响”。

`triton.cudagraph_trees_objgraph` 在当前 NPU 图树中未接入，按相同规则填写。其余图配置需要核对 torch_npu 的实际读取路径；其中已接入的 NPUGraph 配置按实际功能和性能影响填写。

### 当前源码的版本与实现差异

1. **npugraphs 默认入口有一处接口不匹配。** [NPU:_graph_tree.py:262](https://gitcode.com/luqichao/pytorch_new/blob/694f3b371432032d5477fc0d5e47d83aafa7cc09/torch_npu/utils/_graph_tree.py#L262) 默认分支以 (aot_model, num_fixed) 两个参数调用 mutation 检查，但 [PT:cudagraph_utils.py:400](https://github.com/pytorch/pytorch/blob/cf30153c4c131c8164ee7798e5022d810682e2cb/torch/_inductor/cudagraph_utils.py#L400) 的上游定义需要 (gm, mutated_inputs, mutated_input_idxs, static_input_idxs) 四个参数。当前快照未找到适配该调用的实现，直接配对该入口可能在编译期出现缺少参数的 TypeError。两个 Dynamo 配置行描述的是其控制路径及兼容后的作用，不能作为该配对已通过运行验证的结论。
2. **NPU 重录计数比原用途文字更窄。** [NPU:_graph_tree.py:2364](https://gitcode.com/luqichao/pytorch_new/blob/694f3b371432032d5477fc0d5e47d83aafa7cc09/torch_npu/npu/_graph_tree.py#L2364) 附近的实现明确将 StaticInputIdxMismatch 排除出 unexpected 计数；参数/mark_static_address 地址变化仍会重录，但不消耗此处的 128 次上限。超过上限的比较是 >，不是 >=。
3. **严格报错并未覆盖所有 NPU skip 分支。** NPU 图树调用 [PT:cudagraph_utils.py:379](https://github.com/pytorch/pytorch/blob/cf30153c4c131c8164ee7798e5022d810682e2cb/torch/_inductor/cudagraph_utils.py#L379) 的路径会受 cudagraph_or_error 控制；npugraphs 的部分入口检查只是记录日志并返回解释 model。不能把 GPU 用途文字直接扩展成“任何 NPU 捕获失败必报错”。
4. **两个旧项需要按实际消费者解释。** cuda.nvgemm_max_profiling_configs 在 cuda 类中仍有默认定义，当前 [PT:nv_universal_gemm.py:434](https://github.com/pytorch/pytorch/blob/cf30153c4c131c8164ee7798e5022d810682e2cb/torch/_inductor/codegen/nv_universal_gemm/nv_universal_gemm.py#L434) 读取的是顶层 nvgemm_max_profiling_configs；rocm.n_max_profiling_configs 已标记 deprecated。它们在 NPU 没有有效算子消费路径，按“不支持／无影响”填写。
5. **objgraph 尚未接入 NPU。** 上游 [PT:cudagraph_trees.py:1982](https://github.com/pytorch/pytorch/blob/cf30153c4c131c8164ee7798e5022d810682e2cb/torch/_inductor/cudagraph_trees.py#L1982) 有 backref dump 实现，NPU 图树没有 cudagraph_trees_objgraph 的读取。NPU 已接入的是 [NPU:_graph_tree.py:219](https://gitcode.com/luqichao/pytorch_new/blob/694f3b371432032d5477fc0d5e47d83aafa7cc09/torch_npu/npu/_graph_tree.py#L219) 的 allocator history。history 的清理风险只来自源码 TODO，本文没有验证其是否实际造成泄漏。

## 验证与性能解读

已核对 48 项配置定义和引用源码位置；CSV 与 Excel 的前六列及顺序与粘贴清单一致，五个补充列无空值，三个判断列只有是/否。Excel 使用原 11 列表、筛选及冻结名称/表头，并检查导出后的单元格内容和格式。

功能影响共 20 项，功能不受影响共 28 项。默认配置判为是 15 项、否 33 项；这不是 NPU 默认捕获功能的开启数。

性能影响共 21 项，性能无影响共 27 项；这 27 项均在功能说明中明确标注 NPU 不支持。三个 FakeTensor 共用项及 18 个图配置保留实际 NPU 路径的影响分析。

本文不提供未经测量的加速比例。验证已支持配置的性能时，应分别记录 host 编译时间、首次 warmup/capture、稳定 replay 的端到端时间、device kernel 时间及图池峰值内存。涉及 npugraphs 的运行验证需先处理上述 mutation 检查接口兼容问题。
